## 주장할 수 있는 것과 없는 것

- 할 수 있음: 팀 배포 서버와 같은 장비에서, 운영과 분리한 측정용 DB·Redis 로 개선 전후를 쟀고 PC 측정과 같은 방향의 결과가 나왔다.
- 할 수 없음: "운영 환경에 적용했다", "운영 트래픽·운영 데이터로 검증했다". 운영 스택은 제출 당시 그대로다.

## 한계

- 프로필이 `prod` 가 아니라 `local,perf` 다. 데이터는 시드이고 운영 분포(발자취 약 4천 건)가 아니다.
- 부하 발생기·앱·DB 가 같은 서버에서 CPU 를 나눠 썼고(전 측정 중 서버 CPU 40~97%), 운영 컨테이너도 같이 떠 있었다. 절대 수치가 아니라 같은 조건의 전후 비교다.
- Redis 중단은 전후 각 1회, 부하는 30초 구간이다. 장시간 안정성·파일 업로드·외부 API 장애는 서버에서 다시 재지 않았다.
- 측정이 끝난 뒤 측정용 컨테이너·볼륨·네트워크·폴더를 지웠다. 서버가 종료되면 다시 잴 수 없다.
